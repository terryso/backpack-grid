## C01 — P2：官方活动接口失败会把累计活动量覆盖成 0

生产路径：`observe.mjs` 捕获官方接口错误后保存 `officialCampaignVolume: null`，`decide.cjs` 执行 `Number(null)` 得到 0，随后把该值作为有效官方数据覆盖 `campaignVolume`。因此既有活动进度和达标状态可能突然归零。

采集层还有同一类输入问题：未先核对 HTTP 200，且直接对 `totalVolume` 使用 `Number()`；null、布尔、空字符串或数组可能被误当成数值。

当前线上样本的官方值正常，没有证据表明这次缺陷已在实盘发生。影响是活动统计和展示，并非网格交易信号。

## 补丁

- `observe.mjs` 仅接受 HTTP 200，复用已有严格十进制校验器，接受有限非负数值/数字字符串。超时、错误响应及非法结构继续保留 null。
- `decide.cjs` 转换前也使用相同校验器；未知官方值保留原先的账本增量回退，并保留上次有效 `officialAt`。
- 真正的官方数值 0 仍合法，不能用“必须大于 0”掩盖这一场景。
- 新增 `tests/campaign_volume.cjs` 并接入完整 `npm test`，执行生产 observe/decide 控制流。全部状态均在临时 fixture，session I/O 全部 mock，网络预加载拦截，时钟固定在活动窗口内。生产源码未经测试专用改写；observe 仅替换已有 ROOT 注入占位符。
