# 云端方向事件确认：候选修复与验收

基线：`66bc696`。状态：仅隔离 worktree 的候选；主目录、线上 Worker、实际交易状态均未改动。

## 问题与修复

原 Worker 将方向切换标记放在每小时覆盖的 `advice` 中。电脑离线时，即使产生了切换信号，下一轮也可能覆盖标记，本机恢复后无从确认。

候选增加一个 SQLite Durable Object，串行保存小时计数与唯一待确认事件。待确认事件包含 ID、产生时间、原方向、目标方向和本机方向文件版本；在收到该 ID 的 `applied`、`conflict` 或 `expired` 回执前不会被后续判断覆盖。云端不持交易凭证。常规判定与待确认事件分离，已有 KV 副本只供显示。

本机人工指令、云端事件和本地独立判定共用 `fcntl` 锁。自动写入在锁内比较方向文件版本及原方向；人工写入即使再次设为同一方向，也会产生新版本。切换及事件结果保存在同一原子替换文件中，重复投递不会覆盖后来的人工指令。超过两小时或未来时间的事件不执行，记录 `expired` 后确认。需要五次新判断时重新计数；旧事件不会强行补做。

电脑离线时，云端可继续使用最后一次有效的方向版本并用新的行情判断；版本最终由本机锁内校验。快照时间变旧本身不会中断云端计数。恢复时若事件产生已超过两小时，则拒绝该事件，而非执行陈旧信号。

另经只读核对，本机 `com.backpack-grid-direction` 仍为每小时加载任务，11 月 22 日仍有判断记录。为避免两个独立计数器同时改变方向，候选使本机任务默认只写 `direction_shadow_advice.json`，不切换方向、不覆盖云端展示结果；显式设置 `BG_DIRECTION_AUTHORITY=local` 且不存在 `state/dashboard.env` 时，才启用本机独立切换。本次没有更改任何实际配置或任务状态。若未来需要本机独立模式，应先明确停用云端方向通道，再单独评估切换。

## 上线顺序与回滚注意

上线需针对本候选再次确认，先核对主目录基线、脏文件、并行改动及未处理的旧版切换信号。旧版已被覆盖的事件无法追溯恢复；新 Durable Object 从空计数开始，部署切换期间旧版连续计数不会继承，可能需要重新积累五次判断。

建议先发布包含新 Durable Object 的 Worker，再将本机候选安全合入运行目录；旧本机看不到可执行的新版临时标记，新本机遇旧 Worker 也不会执行旧标记。此期间方向自动切换可能暂时停顿。随后等待自然运行产生新的版本化快照，检查公开事件读取、实际回执及每小时判断；不得为验证主动下单或创建网格。生产实际发布和读取结果目前均未验收。

如需回退，先保留待确认事件和新的 Durable Object 迁移记录，停止扩大发布；在隔离分支准备并验证回退补丁，避免直接恢复旧的瞬时切换协议或重新启用本机双重决策。对象删除会丢失待确认数据，不作为常规回滚步骤。

## 边界

测试没有证明 Cloudflare 实际部署、配额、线上持续运行或长期策略有效性。方向锁只约束通过项目事务通道的写入；绕过通道直接编辑状态文件不受锁保护。行情 K 线是否足够新鲜是另一个问题，本补丁没有把它标为已修复。

Cloudflare 的状态 API 文档说明 `blockConcurrencyWhile` 会阻止其他事件交错，回调应尽量短；本候选的锁内只访问对象存储和计算，不访问外部网络：[Durable Object State](https://developers.cloudflare.com/durable-objects/api/state/)。
