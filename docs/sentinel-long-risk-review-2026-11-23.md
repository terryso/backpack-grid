# 多头持仓哨兵缺口：候选修复与验收

日期：2026-11-23。基线：`c1b720c`。本候选只在隔离 worktree 中验证，不修改实盘仓位、方向、风险参数或持久账本。

## 问题和范围

- 20:01 的有效生产快照含 3 个空头和 1 个多头持仓；20:05 的云端哨兵结果只评估了 3 个持仓，却将监控状态记录为 healthy。生产 `slDistance` 原来只接受 `short`，因此多头不会参与 A/B 参考价预警，评估计数也不会把它作为缺失数据。
- 断网模拟实际 Worker 入口：多头保本价 100、现价 95、配置比例 6%，按当前哨兵的参考公式距参考价约 1.05%；原实现没有 A 预警。原始失败日志保存在本轮审查证据目录。
- 哨兵的参考价由保本价和项目配置比例推算，**不是交易所返回的止损触发价**。项目的仓位级自动退出使用保证金收益率；[Backpack 网格机器人 FAQ](https://support.backpack.exchange/exchange/trading/trading-bots/faqs) 的通用说明将机器人止损与启动时子账户权益关联。该说明与当前 API 逐格参数是否完全对应尚未核实，不能把上述参考价或 2% 告警线解释为交易所实际止损距离。

## 候选行为

- 多空持仓均参与现有最差持仓参考价评估；多头方向使用相对于保本价向下的对称价格参考，原有触发阈值和自动交易参数不变。
- 多头缺少有效保本价、实时行情或有效配置比例时，记录监控数据降级；无实时行情时保留已有快照价回退。A/B 提醒明确写为参考价，并说明并非交易所止损价。
- 仍沿用每类提醒 60 分钟冷却及只呈现最差持仓的既有机制，不保证每个持仓分别发送通知；数据降级会持久化状态，但本候选不新增降级专用推送。
- 不改变交易所的订单、止损设置或本机自动退出策略；真实多头方向和实际交易所触发价仍需独立核验。

## 验证与上线边界

- 28 个哨兵专项场景在网络禁用环境通过，覆盖多头临近／越过参考价、缺值、异常比例、快照盲窗、多空混合排序、既有空头和冷却行为。
- 完整 `npm test` 在临时副本中由操作系统禁网执行，26 个测试文件共记录 689 行 PASS。测试副本使用模板配置；macOS 沙箱不允许运行系统带特殊权限的 `/bin/ps`，仅在临时副本中将其路径指向重新签名的同一可执行文件副本，不改断言或运行目录。
- Worker 使用缓存的 Wrangler 4.166.0 在禁网环境 dry-run 打包通过；项目声明版本是 4.147.0，无法仅凭此证明该精确版本的打包。未部署。
- 合入前需用户针对本候选明确确认，并再次检查主分支、并行修改和持久状态；发布前保留有效的仪表盘静态回退数据，发布后读回并观察自然哨兵运行。若需回退，应在隔离目录准备并验证反向提交，保留已存在的告警冷却状态及所有账本。
