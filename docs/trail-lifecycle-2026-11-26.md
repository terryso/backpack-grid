## 问题及处理

1. 旧实现生成追踪止盈计划时就删除峰值；若执行器在持久化停止意图前失败，下一次巡检可能无法再生成同一止盈计划。候选保留峰值，直至有效观测确认该仓位已平或换成不同仓位。
2. 旧峰值仅按币种区分。候选将峰值与账户、币种、仓位方向及仓位 ID 的散列引用绑定：已确认的不同仓位从头计算；无法识别时暂不执行追踪止盈并保留原峰值。用户明确选择：**网格重建但原仓位仍在时，保留原仓位峰值**。仓位 ID 和引用不放入公开仪表盘。
3. 计划生成后、发送关闭网格请求前再次读取仓位身份。身份不符或未知时不发送本次追踪关闭请求；已发送过请求而状态不明时保留待处理记录。旧版追踪停止记录没有身份引用时，即使规划时网格不存在，也不会因执行前网格重新出现而绕过校验。独立的账户熔断、普通止损、普通止盈和破沿退出不受该追踪身份门控。
4. 无法读取或确认账户归属的峰值文件保留原样，不作为空状态覆盖；网页在追踪峰值或仓位身份待核对时显示异常，而非显示风控正常。

## 证据和局限

- 只读检查了交易所当前返回的网格与仓位字段，没有发现明确的单网格实例 ID。仓位提供 `positionId`：一笔当前仓位与其开放历史匹配，与抽样的 36 条同市场已关闭仓位不同，两次读取一致。这不是对今后所有仓位生命周期的证明；[Backpack 官方 API 文档](https://docs.backpack.exchange/)提供相关接口文档。
- 用户选择按仓位连续性保留峰值。交易所返回字段未证明可区分完全相同配置的网格实例；外部手工重建、持仓平掉或请求发出后的异常，需要结合交易所记录和待处理状态核对。
- 最后一次仓位读取与交易所关闭请求不是原子操作。现有接口尚未证明支持按仓位 ID 条件执行，因此极短时间内的并发换仓风险不能宣称完全消除。模拟测试不证明真实成交价格或盈利。
- 旧版没有仓位引用的历史峰值无法可靠判断归属：候选保留为待核对记录，不拿它直接触发新仓位止盈；新峰值按当前仓位重新累计。只读检查时运行目录峰值文件绑定当前账户且有 0 个在追踪市场，后续部署前仍须重查。
- 追踪启动值或回撤值显式设为 0 的配置校验不一致属于独立问题，本候选未修改；本候选不调整任何阈值、方向、资金、杠杆或已有定时任务。
